# Content and data rules

- **Every tunable lives in datapack JSON**, so balance changes never need a recompile. The combat data (frame data, styles, combatant profiles, combat rules) loads through a JSON reload listener (`data.CombatDataLoader`), not a datapack registry: `/reload` retunes a running server, all or nothing, and a file that fails keeps the old generation (spec Data & State, D-052). Files sit at `data/<pack-namespace>/kimetsu/<folder>/<id>.json`. `CombatDataTest` decodes every file against `core/`'s `Fixtures`, and the builder checks the cross-file rules (a style's ids, a demon's attacks, cue leads, every allowed string pairing fitting the beat).
- Each file may carry a `"meta"` object that codecs ignore: `{"status": "PROPOSED" | "CONFIRMED", "source": "docs/design/specs/<spec>.md#numbers"}`. Every number starts PROPOSED; it becomes CONFIRMED only after a sim or playtest, recorded in the spec.
- **Frame data is the source of truth** for hits and cues. One file per attack: windup, active and recovery ticks (1 tick = 50 ms), hits and multi-hits, sweep shape, cue type and lead, beat lock, Breath cost, damage and Posture damage, super armour, cancel windows, contextual trigger, `horizontal` (can decapitate), Mushin finisher. Mob and boss cue leads are at least 8 ticks (0.4 s). Animations follow the data, never the reverse.
- Baked blade arcs (`data/*/kimetsu/arcs/`) are generated by the build from the animation files. Never hand-edit them; fix the animation and rebuild.
- Validators run on save (`.claude/hooks/validators.json`). A broken file fails the hook; fix it, don't bypass it.
- Prefer tags to hard-coded lists (`#kimetsu:demons`, `#kimetsu:nichirin`, damage-type tags).
- Names: use `docs/glossary.md` exactly. Canon names follow the official Viz translation (checked in the Style and Art Roster); keep both names where the anime renames a move.
- Lang: `en_us.json` is the source; `ja_jp.json` is reviewed by a person, never shipped machine-translated. Every sound event has a subtitle key, cue sounds included (deaf and hard-of-hearing players rely on them).
- **Generated data:** `src/generated/scope/` is the vanilla-scope datapack for the milestone `art/vanilla-scope.json` names. Never edit it by hand: change the rules (each rule's `from` is its milestone), run `python tools/vanilla_scope.py --stages` to see what goes and what breaks at each milestone, then `--datapack src/generated/scope --lock`. When a milestone starts, bump `milestone` in the rules file and regenerate. The pack has its own folder because datagen's `runData` deletes every file in its output folder (`src/generated/resources/`) that its providers didn't write; the tool warns if pointed there. A rerun deletes only the files its manifest lists, and it refuses to run on a manifest it can't read. It also rewrites the vanilla trade tags without removed trades (loot modifiers never reach trades). Use 26.3 formats (data pack 121; `docs/gotchas.md`); misode's generators with 26.3 selected give correct JSON.
- **Achievements** (R7-04): the Corps Record and the Blood Record live in `data/kimetsu/advancement/corps/` and `blood/`, with titles in lang. Every file carries `neoforge:conditions` with `neoforge:registered` for each mod id it uses (trigger, icon item, predicate type), and children repeat their parent's: an advancement that fails to decode stops the world loading, and one whose conditions fail vanishes with only a debug line, so a GameTest checks each root loaded. Every criterion has a faction `player` predicate, except a root's `faction_joined`, which filters by faction itself. A root's icon must be an item that exists by then (the blade; the Notebook is a screen). Feats the server judges from frame data use custom triggers whose codecs include the optional `player` field; never let the client report a feat. Rewards are cosmetic at most, and nothing counts grind; `announce_to_chat` only for challenges.
- **Townsfolk** (R7-05): names, trades and the canon blocklist are in `data/kimetsu/townsfolk/names.json`; after any change run `python tools/townsfolk_names.py --check`. Line banks live in `data/kimetsu/townsfolk/lines/`, as response rules (the `dialogue-writer` agent's schema).
