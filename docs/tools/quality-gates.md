# Quality gates: how "done" is checked

Champ can't read Java or test diffs, so the kit checks what a report can't be trusted on: whether the tests cover the latest change, whether anything got weaker on the way, and whether the kit itself changed. The checks run as hooks, read only git, the files and the test results Gradle already wrote, and never run Gradle themselves. Why: ADR 0003.

## The gates

| Gate | When | What it checks | What happens |
|---|---|---|---|
| **Receipts** (`quality_gate.py`, Stop) | end of every turn | For each module with code changed **in this session** (committed or not; a file whose content is what it was when the session started doesn't count, whatever its file time says): is there a JUnit run newer than the newest change, and did it pass? `core/` → `core/build/test-results/{test,simTest,hotPathTest}`, each folder on its own (an old failure in one doesn't spoil a fresh green run in another); the mod → `build/test-results/test`, Java only (the datapack JSON is checked by GameTests at slice end). Gradle files count for both. A test class seen failing in the session stays failing until a run shows it passing, so a filtered rerun (`--tests`) or a deleted result can't hide it; touching the XML doesn't make old results new. A module whose newest results come from a filtered run is "partial": that run vouches only for the classes it ran. | Blocked unless Claude's last message says honestly that the unit tests haven't been run (a "not run" about the GameTests alone doesn't cover them), or which ones fail (a count it states, and any test class it names, must match the results on disk). A claim about a named class ("ParryTest passes") stands when that class passed after the change. A success claim ("all green", "BUILD SUCCESSFUL", "191/191 passed") on stale or red results always blocks, whatever else the message says, up to three times for the same results and also while Claude is continuing because of a Stop hook. While a Gradle test task Claude started still runs in the background (not a dev client or a `--continuous` build), it waits for the modules that task covers, unless the message already claims success ("verified" and "ready to commit" count). A blocker opened in `docs/blockers.md` during this session (by `/blocked`) excuses a module only when its **Files:** line names every file the session changed there (an entry that covers most of a module, such as `*`, names nothing); a blocker without that line excuses nothing. Never a success claim, and never work changed after the blocker was first written (recorded when the entry is written, so touching it later doesn't move the line). |
| **Failure memory** (`test_watch.py`, PreToolUse, PostToolUse and PostToolUseFailure on any Bash or PowerShell command that runs Gradle) | before and after every Gradle command (a failing test run exits non-zero, which Claude Code reports as a failed call, so both after-events are wired) | Before: reads the JUnit XML a run that finished in the background left, before the next run wipes it. After: reads the XML and the console's `FooTest > bar() FAILED` lines (a second Gradle run in the same call may already have replaced the XML), records the test classes that failed, and marks the modules a filtered run (`--tests`) wrote as partial. | Silent. |
| **Tamper** (`quality_gate.py`, Stop) | end of every turn | The session's own work (measured against a snapshot of the working tree when it started, so earlier uncommitted work doesn't count), committed or not. Whole test files are compared with comments removed: fewer `@Test`/`@GameTest` methods or GameTest registrations (moving a test to another file is fine; deleting it, block-commenting it or moving it out of the test sources isn't), fewer assertions or parameterized cases; a test switched off (`@Disabled`, `@EnabledIf…`), skipping itself (`assume…`), returning early or wrapped in `if (false)`, catching `Throwable`/`AssertionError` around its own failures; an assertion that can't fail (`assertTrue(true)`) or an `assertThrows` that accepts any exception; a changed expected value (read from the whole statement, so a wrapped `assertEquals(` counts; literals, constants, enum values, tolerances and operators are compared, a renamed method isn't; every matcher of an AssertJ chain; every argument of a helper like `assertDamage`), an exact check swapped for a looser one (`assertEquals` → `assertTrue`, `isEqualTo` → `isGreaterThan`), a changed `@CsvSource` row or test constant (`static final int EXPECTED = 3`), a shrunk `@ValueSource` or `@MethodSource` provider; a changed or removed timeout (`@Timeout`, `assertTimeout`, GameTest ticks) or GameTest setting (`TestData`, `required`, `manual_only`, retries); fewer GameTest instance files. In shipped code: `@SuppressWarnings` without a reason on the line, a new empty catch, a TODO or `UnsupportedOperationException` stub. In Gradle and CI (comments removed): a new loosening (`ignoreFailures`, `-Xep:…:OFF`, `enabled = false` outside docs and packaging tasks, `onlyIf`, test filters and tags, `excludedPaths`, `-x check`, `continue-on-error`, `\|\| true`, an `if:` on a step, relaxed dependency verification), a removed gate (`-Werror`, Spotless, Error Prone, NullAway, the quality script, the GameTest run, a hook test, the kit lint), a removed CI step, or CI no longer running on push or pull requests. Line findings name the test method, so a second `@Disabled` in the same file is a new finding. The comparison runs tree to tree (a snapshot of the working tree at each stop), so a test file that was never committed is read like any other. | Blocked once per finding while it stands (undone and redone, it's reported again), with the list. Claude restores each one, or explains it to Champ in a plain sentence with the decision that requires it. Never loosened to get green: `/blocked` instead. |
| **Before this session** (`session_start.py` finds it, `quality_gate.py` reports it) | the first stop of a session | The same tamper check, from the tree the last passing stop checked to the start of this session: an interrupted turn (Esc skips the Stop hook), a blocked stop nobody answered (the tree is saved only by a stop that raised nothing), or edits outside Claude Code (Champ's, a pull, a branch switch). Not after a compaction. | Blocked once, with the list. Claude tells Champ in one line each and asks before restoring anything. |
| **Set aside** (`quality_gate.py`, Stop) | end of every turn | Work moved out of sight during the session, which no other check can see: a `git stash` entry, or commits on a branch Claude switched away from. | Blocked once per stash or branch tip: Claude brings it back or tells Champ what's there and why. |
| **Kit integrity** (`quality_gate.py`, Stop) | end of every turn | Did a kit file (hooks, settings, any `CLAUDE.md`, agents, skills, rules, output style, workflows, CI, the Gradle wrapper and quality files, `docs/taste.md`, `.mcp.json`), the GDD snapshot (`docs/gdd/`) or a git setting that runs a program (`core.hooksPath`, `core.fsmonitor`, a credential helper, `.git/hooks/`, and the files `[include]` pulls in) change since the session started, by any route? The path guard stops the routes it can parse; this catches the rest (a script that writes, a path built at run time). A narrow allow rule Champ adds with "don't ask again" (in `settings.local.json`; one command, path or MCP tool) doesn't count; one that allows a whole tool or server (`Bash(*)`, `Bash(:*)`, `mcp__ide__*`) does. | Blocked once per change while it stands (a second change to the same file, or the same change undone and made again, is a new one), also during a continuation. Claude tells Champ what changed and why and names his approval if he gave one; anything he didn't expect, Claude offers to restore. |
| **Path guard** (`guard_paths.py`, PreToolUse) | every Edit, Write, Bash and PowerShell call, and every IDE MCP call (`mcp__idea__`, `mcp__jetbrains__`, `mcp__intellij__`, `mcp__ide__`) | Read-only truth (`ref-src/`, `docs/gdd/`, `reference/`, `.git/`) → **deny**. Gates (`.claude/hooks/`, `.claude/settings.json`, `tools/check_spec.py`), hook state (`.claude/.state/`) and doctrine (every `CLAUDE.md`, agents, skills, rules, output style, workflows, `docs/taste.md`, CI, the Gradle wrapper and quality files, `tools/kit_lint.py`, `.mcp.json`) → **ask**, as do Champ's user-level Claude settings and a `.py` file named like a Python standard module. Also: Minecraft imports in `core/`, raw OpenGL, self-approved specs, history-destroying git, a nested `claude` CLI, a download piped into a shell. Gradle runs that skip or rewire checks ask: an init script (`-I`), excluding any task but docs and packaging (`-x compileJava` would test old classes), a property or environment variable that skips, ignores or disables something (on the command, `export`ed, `env`, PowerShell's `$env:` or `setx`), lenient dependency verification, another Gradle user home (`-g`, `GRADLE_USER_HOME`); so do writes into the Gradle user home's `init.d/`, `init.gradle`, `gradle.properties` and the wrapper's distributions. A filtered run (`--tests`) and `-i` are fine. Commands are parsed (pipes, redirects, heredocs, `cd`, variables, interpreters' inline code, PowerShell cmdlets), so a one-liner that writes counts as a write and a read doesn't. | Deny: the call doesn't run, and the reason says what to do instead. Ask: Champ sees the permission prompt with the reason. |
| **Guard self-test** (`session_start.py`) | every session start | Feeds the guard a Write into `docs/gdd/`; it must answer deny. | If not, the session opens with a warning, Claude tells Champ, and the status line shows `⚠ guards off`. |
| **Fail closed** (`onFailure: "block"`, Claude Code 2.1.295+) | every guarded call | If the guard can't run at all (no Python 3.10+, a crash, a timeout), the call is blocked instead of waved through. An error inside the guard makes it ask instead of deciding, and is logged. | See recovery below. On an older Claude Code the status line shows `⚠ update Claude Code`, because there this setting does nothing. |
| **Changed outside a session** (`session_start.py`) | session start (not after a compaction) | Guarded files that changed since the last turn ended: Champ's edits, a pull, another tool. | One line in the session context; Claude mentions it only if it matters for the task. |
| **Context nudge** (`doctrine_inject.py`) | each prompt | Context past 200k tokens, then 400k. | Claude suggests `/session-close` then `/clear` once at each level. |
| **Kit lint** (`tools/kit_lint.py`, CI and `/milestone-check`) | every push | Unknown or misspelled frontmatter fields, values YAML won't read as text (an unquoted `[`, `: ` or ` #`), an agent not pinned to a model, a skill pointing at a missing agent, a hook script missing or unregistered, an unknown hook event, the guard, the quality gate, the session hook or the failure watcher (on PreToolUse, PostToolUse and PostToolUseFailure) unwired: each must run through `run.sh` alone (`true # quality_gate.py` doesn't count), without an `if` filter (the watcher's `Bash(*gradle*)` and `PowerShell(*gradle*)` excepted), not async, with its full timeout, the session hook on every session source, and the guard failing closed on Bash, PowerShell, Write and Edit; `disableAllHooks` left on; a hook test or the lint itself missing from CI (comments don't count), or the CI step or job that runs them carrying an `if:`, `continue-on-error`, a `\|\|` after the check or its own `shell:`; a shell script with Windows line endings, a plugin from an undeclared marketplace or not pinned to a commit. | CI fails with the list. |

Each finding blocks once while it stands (a success claim on bad results up to three times), so nothing loops; Claude Code also caps continuations. An internal error in `quality_gate.py` lets the stop through and is logged, and a watchdog does the same after 20 seconds (the hook's limit is 30).

The status line shows the receipts state (`tests ✓`, `tests stale`, `tests ✗`), the context size (`ctx 84k`, `⚠` from 200k), plan usage from 50%, `⚠ guards` when a guard is unhealthy, and `⚠ update Claude Code`. The commit nudge reports the receipts too.

## What Claude does when a gate fires
1. Receipts: run the targeted tests (`./gradlew :core:test --tests '…'`, `./gradlew test`) and show the command and the counts. If Gradle reports the test task UP-TO-DATE, add `--rerun`. If stopping early on purpose, one plain line: "Tests haven't been run yet."
2. Tamper: restore the test or check. If a spec or Champ's decision really requires the change, name the decision and explain it in one sentence.
3. Kit integrity: one plain line per change (what and why), naming Champ's approval; offer to restore anything he didn't expect.
4. Before this session or stash: one plain line each for Champ; restore only what he confirms (or pop the stash).
5. Two honest attempts failing the same way: `/blocked`. It writes `docs/blockers.md`, with a **Files:** line naming what the attempts changed, and asks Champ.

## Champ's overrides
- A change to a test or gate that he wants: say so; Claude names his decision in the report, and the gate won't repeat the same finding in that session.
- Doctrine edits are "ask": approve the prompt when it's a change he asked for (or a `/retro` change he picked).
- Every hook off, for one session only, in an emergency: start Claude Code with `claude --safe-mode` (also skips CLAUDE.md, skills and MCP servers: fine for fixing a broken hook). From Git Bash, `claude --settings '{"disableAllHooks": true}'` turns off only the hooks and keeps the rest. Don't put `disableAllHooks` in a settings file: it would stay on.

## Recovery
| Symptom | Fix |
|---|---|
| Every edit and command blocked with a `guard_paths` hook error | Python 3.10+ can't run: `py -3 --version`. Fix it (or open one `claude --safe-mode` session to fix it with Claude), then restart Claude Code. |
| `⚠ guards off` | `python .claude/hooks/tests/test_guard.py`, fix what fails. |
| `⚠ guard errors` | read `.claude/.state/guard_errors.log`: the path guard asked instead of deciding, or the quality gate let a stop through. Fix the hook, then delete the log. |
| `⚠ update Claude Code` | `claude update`. Older versions ignore the guard's fail-closed setting. |
| The receipts gate keeps asking although the tests ran | the test results must be newer than the changed files: rerun the targeted tests (`--rerun` if Gradle says UP-TO-DATE); check that Gradle wrote `build/test-results/`. |
| A session starts by listing kit files "changed outside a session" | expected after your own edits, a pull or a Cowork change; otherwise ask Claude what changed. |

## Files
- Code: `.claude/hooks/_quality.py` (the shared checks), `quality_gate.py`, `test_watch.py`, `guard_paths.py`, `session_start.py`, `statusline.py`, `commit_nudge.py`, `doctrine_inject.py`, `_common.py`.
- State (gitignored, in `.claude/.state/`): `session_base/<session>.json` (HEAD, a snapshot of the working tree, the stash, start time, open blockers, the kit manifest and any findings from before the session; kept 30 days), `failing/<session>.json` (test classes seen failing; kept 30 days), `runs/<session>.json` (Gradle command start times and the modules a filtered run left partial), `blockers_first.json` (when each open blocker was first written), `kit_manifest.json` (the kit at the end of the last turn that raised no integrity finding), `last_checked.json` (the tree the last stop that raised no tamper finding checked; a session start compares against it), `quality_gate.json` (findings already shown per session, and `counts` of each gate's blocks for `/retro`), `guards.json`, `guard_errors.log` (capped at 300 lines), `context/<session>.json` (kept 30 days), `context_nudge.json`.
- Tests: `.claude/hooks/tests/test_quality.py` (with the attacks from the second and third adversarial reviews), `test_guard.py` with `guard_cases.json` (the first review's cases), `test_comms.py`; `tools/tests/test_kit_lint.py`. CI runs all of them.
