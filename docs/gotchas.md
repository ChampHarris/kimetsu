# Gotchas

Things that already cost someone time. Read the relevant section before working in that area; `/session-close` appends new ones. Each line: the trap, then the fix. Versions current as of 2026-10-18; re-verify after any port.

## Platform and build
- 26.x is unobfuscated: Mojang names everywhere. Use `implementation`, not `modImplementation`; Parchment only adds javadocs.
- 26.x needs Java 25. Use the Gradle wrapper the MDK ships (Gradle 9.1+).
- NeoForge for 26.1.0 and 26.1.1 never left beta; 26.3 has been stable since 26.3.0.76. Pin exact builds.
- docs.neoforged.net still describes 26.1. For anything newer, read the primers: `https://docs.neoforged.net/primer/docs/26.2/` and `/26.3/`.
- GameTests are registry-based since 1.21.5 (`@GameTest` and `GameTestRegistry` are gone). `runGameTestServer`'s exit code is the number of failed required tests. The docs name the property `neoforge.enableGameTest`; the MDK uses `neoforge.enabledGameTestNamespaces`. Check which one your MDK sets.
- ModDevGradle's `unitTest { enable() }` runs JUnit inside a modded environment; `core/` tests don't need it and run faster without it.

## Rendering
- 26.2 removed `MultiBufferSource` (nearest replacement: `PreparedRenderType`) and `Tesselator`, rewrote vertex formats, and compiles GLSL to SPIR-V.
- 26.3 moved Blaze3D into `com.mojang.renderpearl`, compiles every shader with ShaderC (`#include`, not `#moj_import`; explicit `layout(location = N)`), and replaced GLFW with SDL3. Raw GLFW calls break; use vanilla key mappings.
- Depth is reversed since 26.2: near = 1.0, test `GREATER_THAN_OR_EQUAL`, clear to 0.
- Overriding core shaders is unsupported; post-effect shaders may change at any time. Register your own pipelines and chains.
- Renderers submit work instead of drawing since 1.21.9 (`SubmitNodeCollector`; `EntityRenderer#render` became `submit`). Render state (1.21.2+): copy what you need into the render state; no entity access while rendering.
- 26.1 renamed `GuiGraphics` to `GuiGraphicsExtractor` (`render*` → `extract*`).
- Iris is OpenGL-only and ignores mod shaders when a pack is active; call `assignPipeline` for custom pipelines or they may not draw ("Missing program ... in override list").
- 26.3 replaced Improved Transparency with order-independent transparency; 26.4 snapshots rename its shader defines.
- NeoForge's loading screen broke under Vulkan on 26.2 (a third-party fix mod exists). Check it on 26.3 before blaming your code.
- Vanilla `light_emission` bugs: MC-301962 (block alpha), MC-305145 (emissive parts invisible in the GUI).

## Animation libraries
- GeckoLib 5 is not GeckoLib 4: data reaches renderers through render-state DataTickets, renderers take three generics, assets live in `assets/<id>/geckolib/`, the package is `com.geckolib`. 4.x tutorials will mislead you.
- GeckoLib Molang variables are global across all animated objects: per-entity state (breathing phase, combo step) leaks. PAL scopes variables per controller.
- PAL: `get3DTransform` returns only the animation's offset, so add the vanilla pose for world-space locators. Extra pivot bones need a `parents` entry and must sit under `body`. Register layers inside `FMLClientSetupEvent.enqueueWork`. The default Molang engine throws on non-player controllers. Layer factories also run for mannequins, so never cast to `Player`. Bends are effectively single-axis. Its docs' version table is stale.
- Better Combat also animates players through PAL: put your layers at priority ≥ 1500, or declare it incompatible.
- AzureLib: pin exact versions; some builds named "-alpha" are flagged as Release on Modrinth.
- The headless Blockbench MCP sampler skips Molang channels and treats Bézier curves as straight lines. Bake arcs from linear keyframes or with PAL's core module.
- Blockbench MCP has no authentication: bind it to localhost, turn off `risky_eval`, and remember Blockbench won't reload a file edited on disk.

## Timing and networking
- A beat at 90–110 BPM is 545–667 ms (11–13 ticks); a ±120 ms window is only 2.4 ticks wide each side. Do beat maths in milliseconds; stamp inputs with tick + sub-tick fraction.
- Hit-stop is client presentation only. Never pause server logic or delay sending inputs for it.
- Vanilla invulnerability frames swallow rapid mod hits: bypass `invulnerableTime` for mod damage (a bypass-cooldown damage-type tag or clearing it per hit; check the 26.3 tag name) and track hits per attacker and swing yourself.

## Assets and audio
- One sprite with an odd size lowers mipmaps for its whole atlas. Atlas sprites must be ≥ 16 px and multiples of 16 (`tools/texture_lint.py` checks).
- Items have their own atlas since 1.21.11; beds and signs moved into the blocks atlas in 26.2; 26.3 removed the model element `shade` field; 26.1 needs a separate `humanoid_baby` armour texture.
- Stereo sounds never attenuate with distance, so positional sounds must be mono. OGG Vorbis only.
- The TTF font provider drops kerning and ligatures and can't do vertical text; brushed form names are textures, not fonts.
- Image generators garble kanji. Render the exact characters from a font (Pillow), then stylise; never let a generator write text.
- AI drafts arrive soft, off-palette and rarely tile. `tools/palette_fit.py` fixes the grid, palette and alpha and reports the seam; a seam ratio above 1.3 shows when the block repeats.
- Snapping to a palette doesn't make a texture look vanilla: a smooth plank snapped to a 7-colour ramp still fails on grain and contrast. Fit to one material ramp, then run the blend check (`tools/vanilla_style.py`; `palette_fit.py` runs it).
- The early loading screen theme loads only from `config/fml/`, never from the mod jar.
- Optional resource packs (Programmer Art, High Contrast) can sit above mod resources and override the restyled paintings; the mod's own namespace is unaffected.
- LambDynamicLights can't be bundled jar-in-jar; make it an optional dependency.

## Data packs, worldgen, spawns and advancements (26.3)
- Pack formats: data pack 121.0, resource pack 97.1 (misode/mcmeta's version summary). One source said 119; it was wrong.
- 26.3 renamed `worldgen/configured_feature` to `worldgen/feature`, allows plain-string block states, and adds the `worldgen/block_state_provider` and `worldgen/material_rule` registries (noise settings have `material_rule`). Old tutorials' paths 404.
- Loot JSON uses a singular `condition` and `modifier`, and predicates can be references (`minecraft:tool/can_shear`). A `tag` entry names its tag in `items` (`{"type": "minecraft:tag", "items": "#minecraft:creeper_drop_music_discs", "expand": true}`), not `name`. Entries carry weights, `empty` ones too: the baby panda's sneeze is one slime ball against an `empty` of weight 699.
- Brewing is data: `minecraft:brewing` recipes with `input`, `reagent` and `output`. `RegisterBrewingRecipesEvent` and `PotionBrewing` are gone; `PotionBrewEvent.Pre` still blocks a brew at runtime. Villager trades are data too: `trade_set/<profession>/level_<n>` names a `villager_trade` tag (`#minecraft:farmer/level_1`), and the tag lists `villager_trade/<id>` files (`gives`, `wants`, `additional_wants`, `given_item_modifier`, sometimes a `merchant_predicate`). Loot modifiers never see trades: to stop one, rewrite its tag with `replace: true` (`vanilla_scope.py` does).
- In 26.x the lead is crafted from string alone.
- `neoforge:false` is now `neoforge:never`. Any datapack-registry entry (recipe, advancement, loot table) whose conditions fail is skipped, with only a debug log line: a wrong id hides the entry silently, so test that it loaded.
- A decode failure is fatal. 26.3 loads recipes, advancements, loot tables, biome modifiers and the other datapack registries through `RegistryDataLoader`, which collects every entry it can't decode and throws once at the end (the log lists them all), and the world doesn't load. An advancement whose icon, trigger or predicate the current build doesn't register (`kimetsu:nichirin_blade`, `kimetsu:faction_joined`, `kimetsu:faction`) is such an entry. Guard it with `"neoforge:conditions": [{"type": "neoforge:registered", "registry": "minecraft:trigger_type", "value": "kimetsu:faction_joined"}]` (`registry` defaults to `minecraft:item`; `minecraft:loot_condition_type` works too), and give each child its parent's conditions. Global loot modifiers are the exception: they load through a reload listener that logs and skips a bad file.
- Global loot modifiers load from `data/<ns>/loot_modifiers/*.json`; there's no `global_loot_modifiers.json`. Each file has one `condition` and a `priority` (default 1000, higher runs first). `LootModifier` takes `Optional<Holder<LootItemCondition>>` and an `int`; build the codec with `codecStart`.
- Datagen (`runData`) deletes every file in its output folder that none of its providers wrote: vanilla `HashCache.purgeStaleAndWrite` walks the whole folder, and NeoForge 26.3's patch only changes how the cache file is written (confirm the vanilla body in `ref-src/` once the sources are extracted). Never hand-place files in datagen's output; the vanilla-scope pack lives in `src/generated/scope/`, a resource folder of its own.
- Disabling a recipe means disabling its `recipes/<category>/<id>` advancement too; a dangling recipe reference may fail the load. `tools/vanilla_scope.py` writes both.
- Disable all 126 vanilla advancements, not only each tab's root (children point at their parent). Empty tabs hide themselves.
  - `AdvancementEvent.AdvancementEarnEvent` fires only for advancements with a `display` block (NeoForge calls it inside `display().ifPresent`). Hidden advancements have one (`hidden` is a display field), so it fires for them; it doesn't fire for display-less ones such as recipe unlocks, despite its javadoc. For those, listen to `AdvancementProgressEvent` and check `getAdvancementProgress().isDone()`.
  - `ToastAddEvent` can only cancel a toast, and `ToastManager.addToast` fires it again for your own toast, so cancel only vanilla's `AdvancementToast`. 26.3 moved the `ToastManager` into the new `Gui` class (`Gui.java.patch`: `private final ToastManager toastManager`); nothing in NeoForge 26.3 calls `getToastManager`, so check the accessor in `ref-src/` before writing the call.
  - Vanilla shows a tab once its root, or anything under it, is done. A demon who completes a Corps child would make the Corps tab appear, so every criterion except a root's `faction_joined` (it filters by faction itself) carries a faction `player` predicate (`{"type": "kimetsu:faction", "faction": "slayer"}`), and custom triggers' codecs include the optional `player` field. The predicate only stops new completions: what a player earned before changing faction stays done.
  - A tab background `<ns>:gui/advancements/backgrounds/<name>` loads `assets/<ns>/textures/gui/advancements/backgrounds/<name>.png`: a plain texture, not a GUI sprite.
  - `SimpleCriterionTrigger` moved to `net.minecraft.advancements.triggers` in 26.2. Its player field is `Optional<Holder<LootItemCondition>>` in 26.3.
- Spawn lists live in the `minecraft:gameplay/natural_mob_spawns` environment attribute, and entries use `count` (an IntProvider), not `minCount`/`maxCount`. `neoforge:remove_spawns` and `add_spawns` still work, but only on biome spawns, not on dimension or timeline spawns. `remove_spawns` takes `biomes` and `entity_types` (a holder set: `#tag`, id or list); `add_spawns` takes `biomes` and `spawners` (one spawner or a list of `type`, `weight` and `count`; its javadoc's `minCount`/`maxCount` are stale). A misspelt key fails the biome modifier registry, which is fatal like any datapack registry. Structures with their own spawn lists (`spawn_overrides`: pillager outposts, swamp huts, monuments, fortresses) spawn from those inside their bounds, which a biome modifier can't touch: use the `neoforge:remove_spawns` *structure* modifier (`structures`, `entity_types`) in `data/<ns>/neoforge/structure_modifier/`.
- Phantoms, pillager patrols, wandering traders and village sieges don't come from spawn lists: `PhantomSpawner`, `PatrolSpawner`, `WanderingTraderSpawner` and `VillageSiege` are the server's custom spawners, so `remove_spawns` can't stop them. Drop them in `ModifyCustomSpawnersEvent`, whose list is mutable; it fires at the end of the `ServerLevel` constructor, after tags load, so checking `#kimetsu:removed_mobs` there works (a `/reload` doesn't rebuild the list). Keep `CatSpawner`. Spawner blocks, trial spawners and eggs bypass both, which is why the `FinalizeSpawnEvent` safety net exists. Conversions bypass `FinalizeSpawnEvent` too (lightning turns a pig into a zombified piglin and a villager into a witch; timed conversions such as drowning run through the new `ConversionTracker`): cancel them in `LivingConversionEvent.Pre` (`EventHooks.canLivingConvert`, called in the `ConversionTracker`, `Pig`, `Villager`, `ZombieVillager`, `Zombie`, `AbstractPiglin`, `Hoglin`, `Tadpole` and `MushroomCow` patches).
- Jungles list `minecraft:ocelot` in their `monster` spawn list, a vanilla bug (MC-1788), and nothing in 26.3 skips it: NeoForge's old workaround in `ServerLifecycleHooks` is commented out and only ever silenced a log warning. So a biome's monster list isn't a list of hostile mobs (`spawn_monsters=false` stops jungle ocelots too, and `vanilla_scope.py` leaves the ocelot out of `#kimetsu:vanilla_hostiles` from the data alone): never clear a whole category.
- Vanilla's monster cap is shared: 70 × loaded chunks ÷ 289, so four players standing together get about the same 70 as one. Mod demons return `MobCategory.MISC` from `getClassification(true)` to stay out of it and spawn from a `CustomSpawner` added in `ModifyCustomSpawnersEvent` (Overworld only).
- To stop a spawn in `FinalizeSpawnEvent`, call `setSpawnCancelled(true)`; cancelling the event only skips `finalizeSpawn`. To replace an entity in `EntityJoinLevelEvent`, cancel it and spawn the replacement next tick; doing it at once can deadlock chunk loading. The event fires on both logical sides: check `level.isClientSide()` before cancelling or replacing anything.
- Vanilla entity constants are `EntityTypes.X` since 26.2, not `EntityType.X`.
- Structures: empty the `has_structure/*` biome tags. Don't disable structure sets with `never`; the pillager outpost set references the villages set.
- Structure templates (NBT) aren't in misode/mcmeta's `data-json`; its `<version>-data` tag serves them. `refsrc.py --mcmeta` fetches the 1,287 overworld templates and summarises each (blocks in every palette, what its jigsaws become, the pools they pull from, the mobs saved in it) in `structure_palettes.json`. Pools link to each other only inside the NBT (each jigsaw's `pool`), so a structure's pieces can't be found from the pool JSON alone; `vanilla_scope.py` follows them jigsaw by jigsaw and applies each piece's processors (a rule with a plain block or tag match, no chance and no location test always fires and replaces its input). Java still builds mineshafts, strongholds, desert and jungle temples, swamp huts, monuments and buried treasure without templates, picks igloo, shipwreck, ocean ruin and mansion templates by name, and adds data-marker chests and mobs and the ocean ruins' suspicious sand and gravel itself: those are hand tables (`CODE_STRUCTURE_BLOCKS`, `STRUCTURE_ENTITIES`).
- Some feature types place blocks their JSON never names: `underwater_magma` (magma blocks under water across the overworld), `monster_room` (spawners), `sculk_patch` (sculk and veins, and the sensors and occasional shriekers its charge grows; 26.3 places the catalyst, and the ancient city's extra shriekers, as JSON `simple_block` steps in a `sequence`), `large_dripstone`, `blue_ice`, `bamboo` (podzol, when its `probability` is above 0), `chorus_plant`; so do tree decorators (`beehive`, `cocoa`, `trunk_vine`, `leave_vine`, `shelf_mushroom`, `pale_moss`, `creaking_heart`). 26.3's corals pick from a block tag (`{"type": "minecraft:random_block", "blocks": "#minecraft:corals"}`), and `fossil` and `template` features place structure templates. They nest anywhere in a feature, so match them by type at any depth; `vanilla_scope.py` does (`CODE_FEATURE_TYPES`, `CODE_DECORATORS`).
- Some drops need the right tool although no loot condition says so: the block's Java properties require a correct tool, and the tool's `minecraft:tool` component lists the block. A cobweb drops string only to a sword (`{"blocks": "minecraft:cobweb", "correct_for_drops": true, "speed": 15.0}`; shears get the cobweb itself). A mod weapon that replaces the sword must copy those rules, or string from webs is gone.
- Gear a mob's spawn code hands it (a skeleton's bow, a zombie's iron spear) has no loot table, so it drops past every loot modifier. An `equipment/*` table (what a trial spawner puts on its mobs) is rolled through `getRandomItems`, which calls `CommonHooks.modifyLoot`, so the strip modifier empties it at equip time, and trial spawners set `slot_drop_chances` to 0 anyway. `LivingDropsEvent` sees every drop `dropAllDeathLoot` captured (loot table, equipment, custom drops), so filter there, potion contents included: a witch drops the potion it was drinking (8.5%).
- A potion is one item plus `minecraft:potion_contents`. JEI hides potion contents listed in `#c:hidden_from_recipe_viewers` on the potion registry (`Tags.Potions.HIDDEN_FROM_RECIPE_VIEWERS`); the creative tab and the strip-items loot modifier need a contents check: `stack.getOrDefault(DataComponents.POTION_CONTENTS, PotionContents.EMPTY).potion()` is an `Optional<Holder<Potion>>`.
- `neoforge:add_table`'s javadoc shows a `conditions` list, but its codec reads one optional `condition`, like every `LootModifier`. `neoforge:loot_table_id` takes `loot_table_id`.
- Bad Omen comes only from drinking an ominous bottle in 26.x (raid captains drop the bottle). It starts raids, and in a trial chamber it becomes Trial Omen, which ominous spawners and the ominous vault need. Remove the raiders without the bottle and a raid with no raiders could end in a free Hero of the Village.
- A trade set offers `amount` trades from its tag, and a villager summoned at level N gets only level N's offers. Nothing makes a level's roll skip offers the villager already holds, so filling an emptied level from a lower one repeats offers (certainly when the lower pool is no bigger than what the villager took from it). `vanilla_scope.py` leaves an emptied level empty by default: 26.1's trade sets stop generating once every trade in the set is used, so it adds nothing (confirm it in game; `"empty_trade_levels": "lower"` brings the fallback back). A level 1 left empty means that profession can never trade. A trade with a `merchant_predicate` needs a villager of that type (`minecraft:villager/variant`), which comes from the biome it was born in (NeoForge's `neoforge:villager_types` data map); a `wants` stack can carry components (the wandering trader buys a water bottle: `potion` with `potion_contents` water).
- An axe scrapes wax and oxidation off copper, so a kept waxed block can become a removed plain one in the world; copper also weathers on its own, and coral dies out of water.
- Don't delete enchantments (tags, loot and saved items break); remove them from tags with NeoForge's tag `remove` field. Keep Nichirin blades out of `#minecraft:enchantable/*`.
- Day and night are timelines: `minecraft:day` marks night at tick 13000, and `minecraft:moon` has a 192,000-tick phase track. `Level#getDefaultClockTime()`, which an earlier note named, appears nowhere in the NeoForge 26.3 sources: find the clock accessor in `ref-src/` before using one.
- Block tinting: 26.1 replaced `BlockColor` with `BlockTintSource`, registered in `RegisterColorHandlersEvent.BlockTintSources`. Older docs name `RegisterColorHandlersEvent.Block`, which is gone.
- No Mojang access (some CI and sandboxes)? `python tools/refsrc.py --mcmeta 26.3` fetches the vanilla data from raw.githubusercontent.com alone and resumes if interrupted.

## Dev tools (ADR 0002)
- MCTest's `mc_launch` needs `loader: "neoforge"` (it has no default) and defaults to multi-loader task names (`:neoforge:runClient`); this build is a single project, so pass `loader: "neoforge", task: "runClient"`. The client API is on port 25599 and the server API on 25598; a second client needs its own `mctest.port`.
- Dev clients are named `Dev`; `--username Dev###` turns each `#` into a random digit. A dev server needs `online-mode=false`, because dev clients have no Mojang session.
- RenderDoc on Vulkan: set `earlyWindowControl = false` in `run/config/fml.toml`. Launch `java` directly, or Gradle with `--no-daemon` and "Capture Child Processes"; with a daemon the game isn't RenderDoc's child.
- JBR hot reload (`-XX:+AllowEnhancedClassRedefinition`) reloads method bodies, fields and signatures. Registries, Mixins and startup code still need a restart.
- aseprite-mcp needs Python 3.13+ and reads `ASEPRITE_PATH` from its environment; it doesn't load `.env`.
- The official Blender Lab MCP and the community "MCP for Blender" both install an executable named `blender-mcp`. Install only one.
- Modrinth Maven: pin by version ID (`maven.modrinth:jei:wSzwAzVB`); version numbers repeat across loaders.
- Spyglass validates datapacks in the editor only; there's no command-line validator for CI.

## Claude Code
- Hook `additionalContext` must sit inside `hookSpecificOutput` or it's silently ignored. Exit 0 from PreToolUse doesn't approve a call.
- Stop hooks fire after every turn and are overridden after eight consecutive blocks; keep them cheap and honour `stop_hook_active`.
- `outputStyle` is case-sensitive: `"Kimetsu Lead"`. `/output-style` writes `.claude/settings.local.json`, not the committed file.
- `/deep-research` is a bundled workflow, so this kit's research skill is `/scout`.
- `enabledPlugins` in the committed settings still needs each machine to install the plugin once.
- Project `.mcp.json` servers ask for approval in interactive sessions; `-p` runs don't ask.
- On macOS, Linux and WSL, Glob and Grep are left out of the default tool set: Claude searches with `find` and `grep` through Bash (embedded bfs and ugrep), so those searches reach the guard hook and permission rules as Bash calls. `find`, `grep`, `ls` and `cat` are built-in read-only commands and don't prompt. A subagent that lists Glob or Grep and leaves out Bash gets them back, which is why canon-keeper and prior-art-scout have no Bash.
- On Windows with Git Bash, any scoped `Bash(...)` deny rule (this kit has two, against force-pushes) switches the PowerShell tool off for the session, so Claude uses Git Bash, which the hooks need anyway. If you turn PowerShell back on (`CLAUDE_CODE_USE_POWERSHELL_TOOL=1`), add matching `PowerShell(...)` rules: `Bash(...)` rules don't cover it. The guard hook checks PowerShell commands either way.
- In permission rules, `Bash(git status:*)` and `Bash(git status *)` mean the same thing; `:*` is only recognised at the end of a pattern. A deny rule beats any allow rule, and an ask rule beats an allow rule.
- PostToolUse and Stop hooks reach Claude through exit code 2 plus stderr; a JSON `decision` on stdout is easy to get wrong. The kit's hooks use `fail_with()` in `_common.py`.

## Windows
- Hooks run under Git Bash. Without Git for Windows they fall back to PowerShell and the `sh` launcher fails; install Git for Windows.
- Git for Windows checks text files out with CRLF unless `.gitattributes` says otherwise, and `Path.write_text` writes CRLF on Windows. The kit pins `*.py`, `*.json` and `*.mcmeta` to LF, the tools write LF, and `vanilla_scope.py`'s freshness hashes read CRLF as LF, so a Windows checkout of the same rules and data never looks stale. Python on Windows also prints to a pipe in the ANSI code page, which can't encode kanji (Claude Code reads every command through a pipe): each tool switches its output to UTF-8, and `.claude/settings.json` sets `PYTHONUTF8=1` for the scripts Claude writes.
- Tool paths arrive with backslashes on Windows; the hooks normalise them.
- Keep `gradlew` with LF line endings (`.gitattributes`) so Git Bash can run it; `gradlew.bat` works in cmd and PowerShell.
- If an `npx`-based MCP server won't start on native Windows, wrap it: `"command": "cmd", "args": ["/c", "npx", ...]` (older Claude Code docs required this; unverified for current builds).
