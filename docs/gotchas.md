# Gotchas

Things that already cost someone time. Read the relevant section before working in that area; `/session-close` appends new ones. Each line: the trap, then the fix. Versions current as of 2026-10-18; re-verify after any port.

## Platform and build
- 26.x is unobfuscated: Mojang names everywhere. Use `implementation`, not `modImplementation`; Parchment only adds javadocs.
- 26.x needs Java 25. Use the Gradle wrapper the MDK ships (Gradle 9.1+).
- NeoForge for 26.1.0 and 26.1.1 never left beta; 26.3 has been stable since 26.3.0.76. Pin exact builds.
- docs.neoforged.net still describes 26.1. For anything newer, read the primers: `https://docs.neoforged.net/primer/docs/26.2/` and `/26.3/`.
- GameTests are registry-based since 1.21.5 (`@GameTest` and `GameTestRegistry` are gone). `runGameTestServer`'s exit code is the number of failed required tests. NeoForge 26.3 reads only `neoforge.enableGameTest` (and every dev run has GameTests on anyway); the MDK's `neoforge.enabledGameTestNamespaces` is read by nothing, so it filters nothing.
- ModDevGradle's `unitTest { enable() }` runs JUnit inside a modded environment; `core/` tests don't need it and run faster without it.
- `./gradlew test --tests X` filters every project's `test` task, so `:core:test` fails with "No tests found for given includes" and its results on disk are deleted (the Stop hook reads them). Filter one project: `./gradlew :test --tests ...` for the mod, `./gradlew :core:test --tests ...` for core (5c-1 re-review).
- A hand-made mutant must still compile under `-Werror`: Error Prone rejects `if (false)` and `false && x` (`ComplexBooleanConstant`), a local left unread (`UnusedVariable`) and `a || b && c` (`OperatorPrecedence`). Write the mutant as live code (`x + 0 * y`, explicit parentheses) and restore the file from a copy afterwards. (seen 2)
- Gradle 9.2.1 (the 26.3 MDK's wrapper) can't run on Java 26, which is the `java` on PATH on Champ's machine. `gradle/gradle-daemon-jvm.properties` (written by `./gradlew updateDaemonJvm --jvm-version=25`) makes the daemon pick a Java 25 install whatever `JAVA_HOME` says; bootstrap the first run with `JAVA_HOME` set to a JDK 25.
- An unfiltered `gameTestServer` run is never empty: it runs every non-manual test, vanilla's optional `minecraft:always_pass` included, so a mod whose tests stopped registering still "passes" ("All 1 required tests passed"). The build passes `--tests kimetsu:*`: a selection that matches nothing exits -1, which fails the task, and the run gets its own folder (`run-gametest/`). Vanilla's `--report <file>` (a JUnit-style XML) wrote nothing when passed the same way, with an absolute or a relative path and with its folder created first; the cause is unverified, so the log is the record. In 26.3, test functions go in `Registries.TEST_FUNCTION` (a `DeferredRegister`), instances through `RegisterGameTestsEvent.registerTest` as a `FunctionGameTestInstance` with `TestData(environment, Identifier.withDefaultNamespace("empty"), maxTicks, setupTicks, required)`; `event.registerEnvironment(id)` gives an empty environment. The server enables every available pack, vanilla at the bottom. See `dev.champ.kimetsu.gametest.ScopeGameTests`.
- A GameTest force-loads only the chunks its structure touches (`TestInstanceBlockEntity.forceLoadChunks`): with `minecraft:empty` (1×1×1) that's one chunk, and an entity a few blocks away can sit in the chunk beside it, which is loaded but doesn't tick entities, so its AI never runs. It fails by placement, so the same test passes one run and not the next. Force-load the chunks a test uses (`ServerLevel.setChunkForced`; the runner unforces every forced chunk when the batch ends). `TestData`'s `padding` only inflates the bounds it clears; tests sit 5–6 blocks apart whatever their size (`StructureGridSpawner`). `GameTestHelper.testInfo` is public: `addListener(GameTestListener)` runs clean-up on pass or fail (`CombatGameTests` closes its arena there).
- 26.3 renamed `Entity.setInvulnerable` to `setPermanentlyInvulnerable` (`isPermanentlyInvulnerable`; `isInvulnerable` also counts the temporary kind).
- NeoForge's `Entity.onRemovedFromLevel()` means "tracking ended", not "gone": it fires, reason still null, when the entity's chunk goes hidden (ticket level past 33). But hidden is unloaded for entities: `PersistentEntitySectionManager.updateChunkStatus` queues every hidden chunk in `chunksToUnload`, and `processUnloads` (`ServerLevel.tick` → `entityManager.tick()`, the same server tick) removes its entities with `UNLOADED_TO_CHUNK` whether or not the chunk itself stays loaded. `shouldBeSaved` doesn't read the type's `noSave`, which only stops the write, so a `noSave()` entity is gone for good and never comes back. The same object returns (`startTracking`, no `onAddedToLevel`) only if the chunk shows again before its entities finished loading from disk, a race no test can set up. Twice wrong here, both times from reading the code without running it: this line first said a `noSave` entity is never unloaded, then that a chunk kept loaded but inaccessible (a forced chunk 3 away, level 34) hands the entity back; 5c-1's GameTest saw `holder 34 ... INACCESSIBLE, removed UNLOADED_TO_CHUNK` (B-001, corrected 2026-10-24). So a mob that must outlive its chunk has to be saved and rejoin from disk as a new object (5c-2, D-063). Tie engine state to `getRemovalReason()`: `shouldDestroy()` is a death or discard, anything else a departure (`M1Demon`, `TestDummy`). A non-persistent mob also despawns beyond 128 blocks (`removeWhenFarAway`) and copies itself through portals (`canUsePortal`): override both for anything whose state lives elsewhere.
- NeoForge writes an entity's attachments before `addAdditionalSaveData` (`Entity.saveWithoutId`: `serializeAttachments`, then `addAdditionalSaveData`; `load` reads them before `readAdditionalSaveData`), and a `serialize(MapCodec)` attachment's write sees only the value, never its holder. So an attachment set in `addAdditionalSaveData` goes out one save late: refresh it in an overridden `saveWithoutId` before `super` (`M1Demon`). `setData` on an attachment with no sync handler sends nothing. A chunk unload saves its entities (those passing `shouldBeSaved`) before `setRemoved(UNLOADED_TO_CHUNK)`, and a disk-loaded entity gets `onAddedToLevel` from `processPendingLoads` on the main thread, as a new object with a new id and its saved UUID. A dying mob is saved by default (vanilla finishes its death on load), so one whose life lives elsewhere overrides `shouldBeSaved`, or its corpse rejoins.
- The mod's JUnit has no registries: a test that touches a class whose static init calls `DeferredRegister.register` dies with `ExceptionInInitializerError` in `DeferredHolder.<init>`. Keep a codec the tests read in a class that registers nothing (`CombatantSave` beside `KimetsuAttachments`).
- A GameTest's entities outlive it: `succeed()` discards only inside the structure's bounds plus a block, and the GameTest server doesn't clear between batches. Discard a test's entities in its `GameTestListener` (`Arena.close`).
- NullAway (JSpecify mode) checks array element writes: `arr[i] = null` into a plain `T[]` fails the build. Declare `@Nullable T[]` and read each element into a local with a null check. Java 25's unnamed patterns (`case Outbox.Pushed _ -> false;`) pass javac, Error Prone and palantir-java-format, and keep an exhaustive switch over a sealed type free of unused bindings.
- `ref-src/` is extracted before an access transformer exists: after adding one, `ref-src/` still shows the field private while the patched jar (`build/moddev/artifacts/minecraft-patched-*-sources.jar`) has it public. Re-run `tools/refsrc.py` or read the jar.
- `core/` sources compile twice (D-021): IntelliJ keeps a shared source root in one module only ("Duplicate content roots detected"), so leave **Build and run using** and **Run tests using** on Gradle. `compileJava` depends on `:core:compileJava`, so any mod build, `runClient` included, fails on an engine import in `core/`.
- ModDevGradle 2 splits the sources: `build/moddev/artifacts/minecraft-patched-<v>-sources.jar` holds the patched Minecraft classes, and NeoForge's own API (events, loot modifiers, conditions, GameTest hooks) is in `neoforge-<v>-sources.jar` in the Gradle cache. `tools/refsrc.py` extracts both into `ref-src/minecraft/` (it used to take only the first) and exits 1, with `neoforge_sources_jar=MISSING` in `ref-src/VERSION`, when the NeoForge jar isn't there.
- 26.x names worth knowing: `ResourceLocation` is `Identifier` (`fromNamespaceAndPath`, `withDefaultNamespace`); `ItemStack.is(TagKey)` comes from the `TypedInstance` interface; `DeferredHolder` extends `Holder.Reference`, so `key()` gives its `ResourceKey`; `ServerLevel.recipeAccess()` is the `RecipeManager`, and `byKey(ResourceKey<Recipe<?>>)` looks one up.
- **Code quality gates (D-033).**
  - Spotless's default line endings follow Git's settings. With `core.autocrlf=true` and `* text=auto`, it expects CRLF in a Windows checkout and fails every LF file there while CI passes. So `.gitattributes` pins Java and Gradle files to LF and `gradle/quality.gradle` sets Spotless to `UNIX`.
  - Gradle picks Minecraft's natives for the host OS through the `net.neoforged.operatingsystem` variants of `net.neoforged:minecraft-dependencies`. So verification metadata written on one OS lacks the others' natives, and CI's Linux build fails strict verification. The `verificationNatives*` configurations in `build.gradle` ask for all three OSes (MDG types the attribute: use `net.neoforged.minecraftdependencies.OperatingSystem` with `objects.named`, not a String).
  - Verification metadata written from a warm Gradle cache misses metadata files a fresh machine downloads. A POM with Gradle's "published-with-gradle-metadata" marker makes a clean resolution fetch the `.module` file too, but a cache that settled the module from the POM never asks for it. So the first file passed locally and failed CI on `junit-bom-5.14.3.module`. Regenerate with `GRADLE_USER_HOME` set to an empty folder and CI's tasks (`docs/tools/toolchain.md` step 12).
  - In a Groovy build script, a local variable with a configuration's name shadows it inside `dependencies {}` ("Could not find method call() … on provider"). Name the variable something else.
  - Under `-Werror`, javac stops after the first class that warns, so Error Prone reports one file per run. To see every finding at once, drop `-Werror` for one local compile.
  - JUnit has no `assertEquals(long, long, long delta)`, so the call resolves to the float overload (Error Prone's LongFloatConversion). A float is exact only to 2²⁴: in µs its spacing reaches 2 µs past 16.8 s and about 1 ms past 2.4 hours, and live combat times are 50 µs × the world's game time. Use `Asserts.assertNear` in `core/`'s tests.
  - Error Prone checks the test sources too; only NullAway skips them. So under `-Werror` a test with an unused local, `==` between records or entities (ReferenceEquality: compare entities by `getId()`) or an enum used by index (`values()[i]`, `ordinal()`: EnumOrdinal) fails the build. Compare records with `equals`; where an index into an enum is the point (an array per slot, a random pick in a test), suppress `EnumOrdinal` there with the reason on the same line.
  - A mutation run under `-Werror` can mistake a compile failure for a kill: a mutant that leaves a variable unused fails to compile (UnusedVariable). Count only the mutants a test failed, and rewrite the others so they still compile.
  - Under `OnlyNullMarked`, NullAway silently skips any class outside a `@NullMarked` package, so `RequireExplicitNullMarking` is on to fail a package that has no `package-info.java`. If a Mixin ever lands, NullAway will call its `@Shadow` fields uninitialised: add `NullAway:ExcludedFieldAnnotations=org.spongepowered.asm.mixin.Shadow`.
  - MDG adds no Maven Central (only `libraries.minecraft.net` and NeoForged's repositories), so `build.gradle` declares `mavenCentral()` for the quality tools.
  - The Java language server's diagnostics (the IDE's red marks) keep their old project model after a Gradle change: new dependencies and new constructors show as unresolved until a reimport. Gradle's compile is the truth. (seen 2)
  - palantir-java-format cuts a `//` comment that runs past 120 columns at the limit, leaving lines of a word or two (`// that`), and an edit script's text anchors miss once it has rewrapped the code around them. Keep comment lines short, re-grep before scripting an edit, and read `spotlessApply`'s diff.
- **Gradle's configuration cache runs a project's independent tasks in parallel** (`org.gradle.parallel` and `org.gradle.configuration-cache` are on). `./gradlew spotlessApply :core:compileJava` raced: javac read a file Spotless was rewriting ("error reading …Obb.java"). Run `spotlessApply` as its own command, then build.
- **Hot paths (`core/`).**
  - A rare branch in a per-tick method still counts: the knockdown air-time limit built a 24-byte `Effect.Contact` on the tick it fired, and `aBrainDrivenDemonsQuietTicksAllocateNothing` caught it, because that test's quiet ticks are the demon's, not its launched player's. Pass a rare branch's values as primitives (`contact(surface, micros, tick)`) rather than building the effect.
  - JDK 25's `StrictMath.sin` and `cos` are FdLibm's Java port, which allocates a `double[2]` on every call (`FdLibm.Sin.compute`, in the JDK's `src.zip`). With escape analysis off that was 76 bytes per `Frame.set`. Escape analysis removed it inside the compiled sweep, but nothing guarantees that at the mod's call sites. The hit package uses its own `Trig`: degrees in, only `+ − × ÷` and an exact remainder, so it stays deterministic on every machine.
  - `com.sun.management.ThreadMXBean.getCurrentThreadAllocatedBytes()` measures a loop's allocation. `:core:hotPathTest` runs the `@Tag("hot-path")` tests with `-XX:-DoEscapeAnalysis` so the JIT can't hide a stray allocation, and `check` runs it. `-Pbench` also holds the printed timings to the budget.
  - The JIT's own tier changes allocate a few hundred bytes on the application thread now and then, and that counts toward `getCurrentThreadAllocatedBytes()`. A 2-core machine (`-XX:ActiveProcessorCount=2`, or CI's runner) still shows one after 100,000 sweeps, while the interpreter (`-Xint`) and C1 alone show none. So one window that must read exactly 0 flakes on CI. The hot-path test warms up 50,000 sweeps and requires most of 10 windows of 20,000 to be exactly 0: a sweep that allocated would dirty every window. To reproduce CI here, set `JAVA_TOOL_OPTIONS=-XX:ActiveProcessorCount=2`.
- Library Maven coordinates (ADR 0001): SmartBrainLib's wiki coordinate is stale for 26.3 (the real one is `net.tslat:smartbrainlib-neoforge-26.3`); PAL's Maven artifact is `PlayerAnimationLibNeo`, since Modrinth's merged jar isn't on Maven; Bendable Cuboids declares no dependencies, so add PAL yourself.
- Error Prone's `IdentityHashMapUsage` fails the build when an `IdentityHashMap` sits in a field typed `Map`: declare the field `IdentityHashMap` (the fight loop caches compiled sweeps by identity, since hashing a whole `FrameData` record on every active tick costs more than the sweep's culls).
- A Gradle test run filtered with `--tests` replaces `build/test-results/test/` with only the classes it ran: rerun unfiltered before counting tests from the XML.
- Mutants that Error Prone rejects never run: a mutation that removes a helper's only use (`UnusedMethod`, `UnusedVariable`), writes `true || x` (`ComplexBooleanConstant`), mixes `||` and `&&` unparenthesised (`OperatorPrecedence`) or leaves a bare `continue` at a loop's end (`RedundantControlFlow`) fails to compile. Phrase mutants with conditions the compiler can't fold (`s.id() < 0 && ...`), and check the "compiled" count, not only "killed".
- 26.3 moved the vanilla entity-type constants from `EntityType` to `EntityTypes` (`EntityTypes.PIG`); `EntityType.PIG` doesn't compile.
- `Block.builtInRegistryHolder()` is deprecated (vanilla's own sword still calls it). For a block in an item's `Tool` rules, take it from the same bootstrap lookup the tag rules use: `BuiltInRegistries.acquireBootstrapRegistrationLookup(BuiltInRegistries.BLOCK).getOrThrow(ResourceKey.create(Registries.BLOCK, id))`.
- 26.3's game rules are snake_case: `/gamerule natural_health_regeneration false`, not `naturalRegeneration`.
- `tools/refsrc.py` doesn't extract FML: `ModConfig`, `ModContainer` and `ConfigTracker` are only in the cached `loader-12.0.12-sources.jar` (read it with `unzip -p`).
- The mod's JUnit run creates an empty `logs/latest.log` in the project root (gitignored).
- Vanilla's sneak-use skips the block whenever something is in hand (`isSecondaryUseActive() && haveSomethingInOurHands`), so "Sneak + right mouse is vanilla's use" can't open a door with an item drawn. NeoForge's `IItemExtension#doesSneakBypassUse` returning true lets it through on both sides (an empty hand already bypasses).
- `IEventBus.addListener(EventPriority.LOWEST, ...)` runs last and, by default, never sees an event an earlier listener cancelled: the way to act only on a death or game-mode change that really happens.

## Rendering
- 26.2 removed `MultiBufferSource` (nearest replacement: `PreparedRenderType`) and `Tesselator`, rewrote vertex formats, and compiles GLSL to SPIR-V.
- 26.3 moved Blaze3D into `com.mojang.renderpearl`, compiles every shader with ShaderC (`#include`, not `#moj_import`; explicit `layout(location = N)`), and replaced GLFW with SDL3. Raw GLFW calls break; use vanilla key mappings.
- Depth is reversed since 26.2: near = 1.0, test `GREATER_THAN_OR_EQUAL`, clear to 0.
- Overriding core shaders is unsupported; post-effect shaders may change at any time. Register your own pipelines and chains.
- Renderers submit work instead of drawing since 1.21.9 (`SubmitNodeCollector`; `EntityRenderer#render` became `submit`). Render state (1.21.2+): copy what you need into the render state; no entity access while rendering.
- 26.1 renamed `GuiGraphics` to `GuiGraphicsExtractor` (`render*` → `extract*`).
- Iris is OpenGL-only and ignores mod shaders when a pack is active; call `assignPipeline` for custom pipelines or they may not draw ("Missing program ... in override list").
- 26.3 replaced Improved Transparency with order-independent transparency; 26.4 snapshots rename its shader defines.
- NeoForge's loading screen broke under Vulkan on 26.2 (a third-party fix mod exists). Check it on 26.3 before blaming your code.
- Vanilla `light_emission` bugs: MC-301962 (block alpha), MC-305145 (emissive parts invisible in the GUI).
- Posing a vanilla model from code: `setupAnim` resets the pose and one model instance draws every entity of its type, so copy what the pose needs into the render state in `extractRenderState` and set the parts after `super.setupAnim`. `EntityRenderState.x/y/z` is where the dispatcher draws it (`LevelRenderer` passes `state.x − camX`), so a renderer can place a body itself. The zombie renderers only take `Zombie` subclasses.
- F1 hides only vanilla's own GUI layers: a mod layer checks `Minecraft.getInstance().gui.hud.isHidden()` itself.

## Animation libraries
- GeckoLib 5 is not GeckoLib 4: data reaches renderers through render-state DataTickets, renderers take three generics, assets live in `assets/<id>/geckolib/`, the package is `com.geckolib`. 4.x tutorials will mislead you.
- GeckoLib Molang variables are global across all animated objects: per-entity state (breathing phase, combo step) leaks. PAL scopes variables per controller.
- PAL: `get3DTransform` returns only the animation's offset, so add the vanilla pose for world-space locators. Extra pivot bones need a `parents` entry and must sit under `body`. Register layers inside `FMLClientSetupEvent.enqueueWork`. The default Molang engine throws on non-player controllers. Layer factories also run for mannequins, so never cast to `Player`. Bends are effectively single-axis. Its docs' version table is stale.
- Better Combat also animates players through PAL: put your layers at priority ≥ 1500, or declare it incompatible.
- AzureLib: pin exact versions; some builds named "-alpha" are flagged as Release on Modrinth.
- The headless Blockbench MCP sampler skips Molang channels and treats Bézier curves as straight lines. Bake arcs from linear keyframes or with PAL's core module.
- Blockbench MCP has no authentication: bind it to localhost, turn off `risky_eval`, and remember Blockbench won't reload a file edited on disk.

## Timing and networking
- A beat at 90–110 BPM is 545–667 ms (11–13 ticks); a ±120 ms window is only 2.4 ticks wide each side. Do beat maths in milliseconds; stamp inputs with tick + sub-tick fraction.
- Hit-stop is client presentation only. Never pause server logic or delay sending inputs for it.
- Vanilla invulnerability frames swallow rapid mod hits. In 26.3 living i-frames are `LivingEntity.damageCooldownTime`, not `invulnerableTime`. Tag mod damage `bypasses_cooldown`, which skips the check but still sets the cooldown to 20 and shields the target from its next vanilla hit, so also call `setInvulnerabilityTicks(0)` in `LivingIncomingDamageEvent`. Never tag it `bypasses_invulnerability` (that passes creative mode and the totem), and set `"scaling": "never"` or players take difficulty-scaled mod damage. Track hits per attacker and swing yourself.
- Redirecting vanilla damage away from an entity's health belongs in `LivingDamageEvent.Pre` (`setNewDamage(0)` after taking the amount), not `LivingIncomingDamageEvent`: Incoming fires before vanilla's damage cooldown, so cancelling there skips the cooldown and lava or a cactus deliver damage every tick instead of every 10. `/kill` still reaches Pre (`genericKill` passes `isInvulnerableTo`).
- The engine buries a dead mob in the step that kills it (`CombatWorld.bury`), before the mod sees `MobDied`: anything the mod asks the world about that mob after the step must allow for its absence (`strikePose` returns false for an unknown id).
- Vanilla's tick schedule isn't game time under sustained lag. `MinecraftServer.getNextTickTime()` (public) moves on one tick length per tick whether or not the tick finished on time, and skips forward only when 2 s behind, at most once per 15 s ("Can't keep up!", `MinecraftServer.java:734–754`): at 15 TPS it drifts 16.7 ms a tick. Keep your own schedule from measured tick starts and re-anchor when vanilla skips (M1 spec Rules 1.2 and 1.8).
- Queued packets run before `ServerTickEvent.Pre` (`processPacketsAndTick`), and the integrated server's pause skips both Pre and Post (`IntegratedServer.tickServer` calls `tickPaused()`; a dedicated server's pause when empty does the same). The first tick back is the next game tick after a long gap, which a tick schedule takes for a stall unless told: compare the start with the previous tick's Post (`TickInput.previousEndNanos`). The network thread keeps answering pings through the pause with the last record from before it, so the client stops its own clock when it pauses.
- `/tick sprint` runs ticks a couple of ms apart. A schedule that only steers on ordinary ticks moves a whole tick length on per sprint tick and ends minutes ahead: follow the measured starts while sprinting (or frozen, or paused), and re-anchor after.
- Vanilla drops its tick backlog ("Can't keep up!") without any event, and from tick times alone a drop looks like the integrated server's pause: both are a long gap that ends on schedule. The one exact sign is `MinecraftServer.lastOverloadWarningNanos` changing, which a sprint tick also writes; it's private, so the mod's access transformer makes it public (`combat.TickClock`, `META-INF/accesstransformer.cfg`, listed in `neoforge.mods.toml`).
- `ServerTickEvent.Pre` fires before `tickRateManager.tick()` decides whether the tick runs the game, and only the overworld advances game time (`ServerLevel.tickTime`, `tickTime` true for it alone). So the tick number a tick will reach is game time + 1 if `!isFrozen() || frozenTicksToRun() > 0`, else game time (`core`'s `TickNumber`); check in `Post` that the game time got there before stepping.
- A guard counts as held only after `guard_hold_ticks` (150 ms): a press 40 ms before an impact is a tap, and if the whiff lockout keeps it from deflecting, the strike hits rather than being blocked. A test that wants a block holds guard from well before the impact.
- During a tick `getNextTickTime()` is already the next tick's schedule (the run loop adds the tick length before running it), so a tick's own scheduled start is `getNextTickTime() - nanosecondsPerTick()`. A paused integrated server keeps advancing it, so its first tick back starts on time; a stall, inside a tick or between two (packet handling runs before `Pre`), leaves the next tick late.
- A modded server's catch-up ticks can take 25–45 ms, inside a 0.5–1.5× "ordinary" band: tell catch-up from a rate by vanilla's lateness (shorter than nominal with a late tick at either end), not by interval length, and accept a sustained slower rate only after a run of agreeing intervals, since a lone long one is a stall.
- A `/tick rate` change applies to the wait after the tick that ran the command, so the first interval measured after it may be at either rate: reset T̄ to the new nominal length and don't count that interval.
- An attachment syncs on every `setData` (no equality check) and on a `getData` that creates the default, and every receiver gets the same bytes: no per-receiver content, and set it once per change.
- `CustomPacketPayload.createType(String)` puts the id in the `minecraft:` namespace; give it a `kimetsu:` id.
- `hurtMarked` is now `Entity.syncVelocity` (`markHurt()`); `push` and `knockback` alone never reach the player who's pushed.
- Input codes are SDL's: mouse left 1, middle 2, right 3, side buttons 4 and 5 (GLFW's 3 and 4; `InputConstants:151-152`), keys are scancodes (`KEY_A = 4`). The javadoc of NeoForge's `InputEvent.MouseButton` still describes GLFW values.
- A `piercing_weapon` item makes the server ignore attack packets and turns on STAB; keep it off the Nichirin.
- `ModConfig.Type` is LOCAL, CLIENT, SYNCED and STARTUP (no SERVER or COMMON). `DataPackRegistryEvent.NewRegistry` is gone: use `NewDatapackRegistryEvent`, whose `worldRegistry` can sync and whose `reloadableRegistry` reloads on `/reload` but can't sync.
- `PoseRing.at(t, out)` copies the newest pose into `out` but returns false when `t` is past it, and online a player's frame for tick n reaches the server after tick n runs. Testing its return value as "have a pose" silently skipped the demon's guard turn and the lunge clip for every connected player; tests at latency 0 passed. Check `size() > 0` and use the pose; test anything pose-driven at latency 1 or more (slice 4a's netcode review).
- A demon's replay judges meters again, never results: so anything a replay re-derives from state (whether a cancel keeps a stake, whether a block still asks for a counter) must be decided when the event is recorded and stored in it, or a late event earlier in the same tick flips it (slice 4a's code review).
- An effect back-dated to an impact also takes in the presses made after the impact but before its client could know of it. `ClashStart` is logged at the heavy's impact but decided when the player's input horizon passes it, so a Chain hit buffered after the form, before the freeze could show, became the clash's false start, more often the higher the ping; tests that pressed only after the flash passed. Give such an effect the earliest time its client can have shown it (the end of the deciding tick + RTT/2 + its stamp tolerance) and ignore presses stamped before it (`Effect.ClashStart.pressesFromMicros`; slice 4b's reviews).
- The GameTest server runs its ticks back to back: vanilla's next-tick time runs ahead by 50 ms a tick while a tick takes microseconds, so `TickSchedule` measures T̄ in microseconds there and an arrival's combat time is meaningless. Never compare combat time with wall time in a GameTest; core's tests own the conversion (D-056's GameTest checks the record's wiring only). Its 600-tick limit is about a second of wall time, so a test that waits on a chunk generating needs thousands (`CHUNK_TICKS`). (seen 2)
- Even on a real server an arrival during tick n needn't convert into [50n, 50n + 50): Rule 1.2's line is the schedule's smoothed one, so a late tick lands its arrivals past its end and a catch-up tick before its start.
- Registered payloads have no 32 KiB limit in either direction (only `DiscardedPayload`, an unregistered id, has it): bound every count and string in your own codec. `ByteBufCodecs.list()` with no argument allows `Integer.MAX_VALUE` elements.
- A payload inside a `ClientboundBundlePacket` runs on the client's render thread even if its handler is registered for the network thread (the bundle is applied in one main-thread step): send anything timed (a pong) on its own.
- `server.execute` is a different queue from the packet queue and can overtake packets that arrived earlier; `context.enqueueWork` shares vanilla's packet queue, so a mod payload keeps its place after the movement packet sent before it. Queued mod work still runs after the player disconnected: check the session is open. A MAIN handler's exception is only logged; `context.disconnect` from a network-thread handler blocks Netty.
- `Util.getNanos()` on the client reads SDL's counter (`Util.setTimeSource` in the `Minecraft` constructor), and the integrated server in the same JVM reads the same one, so single player's clock offset is about 0; a dedicated server reads `System.nanoTime`.
- `ClientTickEvent.Pre/Post` keep firing while the game is paused and under `/tick freeze`. Single player's pause stops the integrated server's ticks with no event on the server, so the client pauses its clock itself (`ClientPauseChangeEvent.Post`), and its unpause pings can all be answered with the pre-pause record before the server's first tick back: ping until a newer record arrives (measured: input back within 0.4 to 1 s).
- Sending a registered payload to a connection that lacks its channel throws (`NetworkRegistry.checkPacket`, outside the send's try): a GameTest's `makeMockServerPlayerInLevel` logs in with no payload setup and fires `PlayerLoggedInEvent`. Check `player.connection.hasChannel(TYPE)` before a player gets anything (`FakePlayer.send` does nothing, so fake players are safe).
- The client's `EntityLeaveLevelEvent` fires only from `onTrackingEnd`: a dimension change builds a new `ClientLevel` and posts only `LevelEvent.Unload` for the old one, so every entity you kept from it stays `isAlive()` (and keeps the old level alive). Clear such lists on the client's `LevelEvent.Unload`.
- A dead player's entity leaves its level 20 ticks after death (`LivingEntity.tickDeath`, which `ServerPlayer` doesn't override), taking its chunk tickets: in single player a death screen held past a second unloads everything around it, so whatever a mob does on leaving tracking happens on every death (it's why the M1 demon vanishes; 5a's rule kills it in the engine).
- Leaving the End through the exit portal respawns the player (`PlayerList.respawn`, `PlayerRespawnEvent`) with no death and no `PlayerChangedDimensionEvent`: per-dimension state must move on respawn too.
- A minimum-over-a-window RTT can't follow a rise: under bufferbloat the judge's ref sits early for the whole window and honest frames fail. Restart the window when consecutive samples sit well above the minimum (D-057).
- The `no_knockback` damage-type tag stops vanilla's knockback but not `markHurt()`: `hurtServer` sets `syncVelocity` unless the type is also `minecraft:no_impact` (`LivingEntity.java:1308`, that tag's only use), and the tracker then sends the server's own motion to the player who was hit, as well as to everyone tracking them (`ServerEntity:209-211`). A `ServerPlayer`'s server-side motion is stale: the server never simulates a player's movement, only decays it by 0.98 a tick and seeds jumps. So every mod hit resets that client's motion to a stale value.
- Effects are logged at the back-dated impact tick, but a client learns of one only after the tick that decided it plus RTT/2. Time anything physical from an effect (a push's splat window, a launch's minimum air time) from the decision tick + RTT/2, never from the impact (5c-3 plan review).
- A per-tick movement bound can't tell a Water Step from chained sprint-jumping. Vanilla's sprint-jump peaks at 0.61 blocks a tick (0.285 carried, plus the 0.2 boost, plus 0.13 ground acceleration), so 1.2× that is above the Step's 0.7. Over 6 ticks they separate: 2.35 against 3.0. For its owner, single player skips only "moved too quickly" (`ServerGamePacketListenerImpl:1262`); "moved wrongly" still runs, but it compares collisions, not speed.
- `MovementInputUpdateEvent` can't zero movement by replacing `keyPresses`: `KeyboardInput.tick` has already computed the protected `ClientInput.moveVector` before the event fires, and it has no setter, so zeroing it takes an access transformer. Vanilla's double-tap-sprint window is the `sprintWindow` option (0–10, default 7), not a constant.
- Vanilla's set-backs ("moved too quickly", "moved wrongly", the 20-tick resend) all go through `ServerGamePacketListenerImpl.teleport` and count up `awaitingTeleport`, and a client provokes them whenever it likes, each landing where it already claimed to be: the counter is no "the server moved the player" signal for anti-cheat (5c-3a's netcode blocker, D-073). `EntityTeleportEvent` is: `/tp`, `/spreadplayers`, pearls and chorus fruit post it just before the move, with the absolute target (respawns and dimension changes don't), and a listener on the base class gets every subclass (bus 8's `ListenerList` has a parent).

## Assets and audio
- One sprite with an odd size lowers mipmaps for its whole atlas. Atlas sprites must be ≥ 16 px and multiples of 16 (`tools/texture_lint.py` checks).
- Items have their own atlas since 1.21.11; beds and signs moved into the blocks atlas in 26.2; 26.3 removed the model element `shade` field; 26.1 needs a separate `humanoid_baby` armour texture.
- Stereo sounds never attenuate with distance, so positional sounds must be mono. OGG Vorbis only.
- The TTF font provider drops kerning and ligatures and can't do vertical text; brushed form names are textures, not fonts.
- Image generators garble kanji. Render the exact characters from a font (Pillow), then stylise; never let a generator write text.
- AI drafts arrive soft, off-palette and rarely tile. `tools/palette_fit.py` fixes the grid, palette and alpha and reports the seam; a seam ratio above 1.3 shows when the block repeats.
- Snapping to a palette doesn't make a texture look vanilla: a smooth plank snapped to a 7-colour ramp still fails on grain and contrast. Fit to one material ramp, then run the blend check (`tools/vanilla_style.py`; `palette_fit.py` runs it).
- The early loading screen theme loads only from `config/fml/`, never from the mod jar.
- Optional resource packs (Programmer Art, High Contrast) can sit above mod resources and override the restyled paintings; the mod's own namespace is unaffected.
- LambDynamicLights can't be bundled jar-in-jar; make it an optional dependency.
- `texture_lint.py` picks the palette by path (`art/texture-rules.json`): `textures/item/*` must sit on `taisho-world.gpl`, `textures/entity/demon/*` on `demon-flesh.gpl`; a texture elsewhere under `textures/entity/` has no palette rule.

At Build 0 the adventure trim advancements named the removed eye, rib, snout and spire trims; `vanilla_scope.py` now disables any advancement that names a disabled recipe, and its children, at the same milestone.
- A decode failure is fatal. 26.3 loads recipes, advancements, loot tables, biome modifiers and the other datapack registries through `RegistryDataLoader`, which collects every entry it can't decode and throws once at the end (the log lists them all), and the world doesn't load. Guard it with `"neoforge:conditions": [{"type": "neoforge:registered", "registry": "minecraft:trigger_type", "value": "kimetsu:faction_joined"}]` (`registry` defaults to `minecraft:item`; `minecraft:loot_condition_type` works too), and give each child its parent's conditions. Global loot modifiers are the exception: they load through a reload listener that logs and skips a bad file.

Never hand-place files in datagen's output; the vanilla-scope pack lives in `src/generated/scope/`, a resource folder of its own.
- Disabling a recipe means disabling its `recipes/<category>/<id>` advancement too; a dangling recipe reference may fail the load. `tools/vanilla_scope.py` writes both.
- Disable all 126 vanilla advancements, not only each tab's root (children point at their parent). Empty tabs hide themselves.
  - `AdvancementEvent.AdvancementEarnEvent` fires only for advancements with a `display` block (NeoForge calls it inside `display().ifPresent`). Hidden advancements have one (`hidden` is a display field), so it fires for them; it doesn't fire for display-less ones such as recipe unlocks, despite its javadoc. For those, listen to `AdvancementProgressEvent` and check `getAdvancementProgress().isDone()`.

A demon who completes a Corps child would make the Corps tab appear, so every criterion except a root's `faction_joined` (it filters by faction itself) carries a faction `player` predicate (`{"type": "kimetsu:faction", "faction": "slayer"}`), and custom triggers' codecs include the optional `player` field. - Spawn lists live in the `minecraft:gameplay/natural_mob_spawns` environment attribute, and entries use `count` (an IntProvider), not `minCount`/`maxCount`. `neoforge:remove_spawns` and `add_spawns` still work, but only on biome spawns, not on dimension or timeline spawns. `remove_spawns` takes `biomes` and `entity_types` (a holder set: `#tag`, id or list); `add_spawns` takes `biomes` and `spawners` (one spawner or a list of `type`, `weight` and `count`; its javadoc's `minCount`/`maxCount` are stale). ## Claude Code
- Hook `additionalContext` must sit inside `hookSpecificOutput` or it's silently ignored. Exit 0 from PreToolUse doesn't approve a call.
- Stop hooks fire after every turn and are overridden after eight consecutive blocks; keep them cheap and honour `stop_hook_active`.
- `outputStyle` is case-sensitive: `"Kimetsu Lead"`. `/output-style` writes `.claude/settings.local.json`, not the committed file.
- `/deep-research` is a bundled workflow, so this kit's research skill is `/scout`.
- **A background command's reported exit code is its last command's.** `./gradlew … > log; echo "exit $?"` reports 0 when Gradle failed; read the printed `exit N` (or the log's `BUILD` line), never the notification's code.
- `enabledPlugins` in the committed settings still needs each machine to install the plugin once.
- Project `.mcp.json` servers ask for approval in interactive sessions; `-p` runs don't ask.
- On macOS, Linux and WSL, Glob and Grep are left out of the default tool set: Claude searches with `find` and `grep` through Bash (embedded bfs and ugrep), so those searches reach the guard hook and permission rules as Bash calls. `find`, `grep`, `ls` and `cat` are built-in read-only commands and don't prompt. A subagent that lists Glob or Grep and leaves out Bash gets them back, which is why canon-keeper and prior-art-scout have no Bash.
- On Windows with Git Bash, any scoped `Bash(...)` deny rule (this kit has two, against force-pushes) switches the PowerShell tool off for the session, so Claude uses Git Bash, which the hooks need anyway. If you turn PowerShell back on (`CLAUDE_CODE_USE_POWERSHELL_TOOL=1`), add matching `PowerShell(...)` rules: `Bash(...)` rules don't cover it. The guard hook checks PowerShell commands either way.
- In permission rules, `Bash(git status:*)` and `Bash(git status *)` mean the same thing; `:*` is only recognised at the end of a pattern. A deny rule beats any allow rule, and an ask rule beats an allow rule.
- A Bash heredoc of about 10 KB or more gets cut off ("unexpected EOF while looking for matching"). Write long scripts with the Write tool and run the file.
- The guard hook blocks any Bash command that names a spec path together with `status: APPROVED` or "approve", even a read-only one ("Only Champ approves specs, and not through the shell either"). It cost two retries on 2026-10-20. Put a script that only reads in a file and run the file, and keep the literal `APPROVED` out of the command line.
- PostToolUse and Stop hooks reach Claude through exit code 2 plus stderr; a JSON `decision` on stdout is easy to get wrong. The kit's hooks use `fail_with()` in `_common.py`.
- `claude plugin install <plugin> --scope project` rewrites `.claude/settings.json` even when the plugin is already enabled there: same settings, keys reordered (the `if` field moves after `command`, `outputStyle` and friends move to the end). Compare the parsed JSON against `git show HEAD:.claude/settings.json`, and if it matches, `git checkout -- .claude/settings.json` keeps the committed layout; the install itself lives outside the repo.
- A plugin installed while Claude Code is running doesn't load until Claude Code restarts; `/clear` doesn't reload plugins. The sign: a mod's tools (Savvy Progress adds `mcp__savvy-progress__progress` and `__step`) are missing from the session. Restart with `claude --continue` to keep the conversation. Savvy Progress's panel then opens only by `/agents-info`, or by itself for its own `savvy-*` workers unless its `autoOpen` option is `any`.

## Windows
- Hooks run under Git Bash. Without Git for Windows they fall back to PowerShell and the `sh` launcher fails; install Git for Windows.
- Git for Windows checks text files out with CRLF unless `.gitattributes` says otherwise, and `Path.write_text` writes CRLF on Windows. The kit pins `*.py`, `*.json` and `*.mcmeta` to LF, the tools write LF, and `vanilla_scope.py`'s freshness hashes read CRLF as LF, so a Windows checkout of the same rules and data never looks stale. Python on Windows also prints to a pipe in the ANSI code page, which can't encode kanji (Claude Code reads every command through a pipe): each tool switches its output to UTF-8, and `.claude/settings.json` sets `PYTHONUTF8=1` for the scripts Claude writes.
- Python's `open(p, 'w')` writes CRLF on Windows, so an edit script turns a whole LF source file CRLF (Git warns "CRLF will be replaced by LF"; `spotlessApply` puts it back). Pass `newline='\n'`.
- Backslashes in a Bash-tool heredoc can arrive halved even under `<<'EOF'`: a Python edit script's `'\\n'` reached Python as `'\n'`, a real newline, so its anchor for Java's `'\n'` escape matched nothing (2026-10-21). Write edit scripts that contain backslashes with the Write tool and run the file. (seen 2)
- Long `python - <<'EOF'` heredocs in the Bash tool fail with "unexpected EOF while looking for matching `''" well before 10 KB (one at about 6 KB). Write the script with the Write tool and run the file. (seen 2)
- A Python `subprocess.run(["cmd", "/c", "gradlew.bat", ...], cwd=repo)` started from the Bash tool fails with "'gradlew.bat' is not recognized": cmd doesn't look in the working directory there. Pass the wrapper's absolute path.
- Tool paths arrive with backslashes on Windows; the hooks normalise them.
- Keep the repository on a path without spaces. The guard hook's shell-write patterns can't follow an absolute path through a space, so `test_guard.py` failed 29/30 under `Downloads\Kimetsu Development\` and passes 30/30 at `C:\Users\morga\dev\kimetsu`.
- `Path.write_text` writes CRLF on Windows: `make_ramp.py` and `vanilla_style.py --build-stats` did, which left the ramps "modified" after every run; both now pass `newline="\n"`. A `gradlew` cloned with `core.autocrlf=true` arrives with CRLF and Git Bash can't run it; `.gitattributes` pins it to LF.
